# REQ-02 — Solana CLI pinned at 3.1.10, not 4.x

> "| Solana CLI | **3.1.10** | Anchor 1.1.x CI-tested pairing — *not* 4.1.x |"
> — IMPLEMENTATION_APPENDIX.md §1, toolchain table (L22)

**Verdict:** implemented · confidence: high

**What this demands of an implementation:** Every place the repo documents or mechanizes its build
toolchain must name Solana CLI 3.1.10 (the Anchor 1.1.x CI-tested pairing), and nothing may pin,
install, or document a 4.x CLI for the swap-program build. Two prongs: (a) documentation, (b) any CI
or machine-readable toolchain config that exists.

---

**Where enforcement lives:**

Documentation prong — three documents, all consistent:

```
IMPLEMENTATION_APPENDIX.md:L22   | Solana CLI | **3.1.10** | Anchor 1.1.x CI-tested pairing — *not* 4.1.x |
IMPLEMENTATION_PLAN.md:L102-L103 3. Pin the toolchain to the **tested pairing**, not to "latest stable" — see
                                 `IMPLEMENTATION_APPENDIX.md` §1. Anchor **1.1.2**, Solana CLI **3.1.10**, `solana-*` **^3**.
program/README.md:L9-L11         ## Toolchain (pinned — do not "upgrade to latest")
                                 Anchor **1.1.2** · Solana CLI **3.1.10** · Rust **1.89.0** (rust-toolchain.toml) ·
                                 `Cargo.lock` committed.
```

Machine-readable prong — the pins that do exist match the table's companion rows:

- `program/Anchor.toml:L3-L4` — `[toolchain] anchor_version = "1.1.2"` (the Anchor 1.1.x row).
  No `solana_version` key, so Anchor does not itself force CLI 3.1.10 — see Open questions.
- `program/rust-toolchain.toml:L1-L2` — `channel = "1.89.0"` (the Rust MSRV row).
- `program/Cargo.lock` (committed, as the appendix's "Commit `Cargo.lock`" paragraph demands,
  IMPLEMENTATION_APPENDIX.md:L31-L34) — 114 `solana-*` crate entries, every SDK crate on the 3.x
  line (3.0.0–3.4.0). The only 2.0.0 entries are `solana-config-interface` (L3645) and
  `solana-system-interface` (L4598), interface crates versioned independently of the SDK line —
  not a 4.x leak.
- `program/programs/thugz-swap/Cargo.toml:L35-L41` — direct `solana-*` deps all `"3"` /
  `"3.0.x"`, matching the table's `solana-* crates ^3` row.

CI prong — vacuous: no CI exists anywhere in the repo (see Searched). There is therefore no CI
that could install 4.x, and none claiming to install 3.1.10 either.

---

**Paths walked:**

Not a code-path requirement; the "paths" are the places a toolchain version can be declared:
appendix table ✓, plan ✓, workspace README ✓, Anchor.toml ✓ (anchor pin only), rust-toolchain.toml ✓,
Cargo.toml/Cargo.lock ✓ (all 3.x), CI configs (none exist), `scripts/verify_mainnet_artifact.py`
(no toolchain/version references at all — `grep -iE "solana|toolchain|version"` returned nothing).

The one 4.x mention in scope is the appendix itself acknowledging the machine's ambient CLI:
"This machine has CLI 4.1.1 — newer than the tested pairing, not better for this purpose"
(IMPLEMENTATION_APPENDIX.md:L16-L17) — that is the warning, not a pin. The project CLAUDE.md's
"solana CLI 4.1.1" note belongs to the separate metaboss/MCC mission, not the swap-program toolchain.

  (both `-interface` crates, not SDK); zero 4.x

  version used for the run

---

**How the verdict was reached:** The "Holds if" clause is satisfiable by documentation alone
("Documented/CI toolchain uses Solana CLI 3.1.10, not 4.x"), and every document that states a CLI
version states 3.1.10 with the explicit not-4.x warning; no config or lockfile pulls a 4.x line.
Not `partial`: there is no path or artifact in the repo that documents or pins 4.x — the CI prong
is empty rather than divergent. Not `stronger-than-spec`: the pins present (anchor 1.1.2, Rust
1.89.0, crates ^3) are exactly the table's other rows.

**Open questions:**

- The CLI pin is enforced only by prose. `Anchor.toml` supports `[toolchain] solana_version`
  (Anchor.toml:L3-L4 carries only `anchor_version`), and no CI or build record
  (`devnet_matrix_results.txt`, `scripts/verify_mainnet_artifact.py`) captures which CLI actually
  ran. On a machine whose ambient CLI is 4.1.1 (IMPLEMENTATION_APPENDIX.md:L16-L17), nothing
  mechanical stops a build with the untested pairing. The requirement as worded still holds; a
  `solana_version = "3.1.10"` line in Anchor.toml would make it self-enforcing.
