## What the requirement demands

The workspace must declare (in Cargo metadata or an equivalent documented pin) a
minimum supported Rust version of 1.89. This is a toolchain-declaration
requirement, not a runtime behavior; "enforcement" here means cargo's own
`rust-version` gate plus the toolchain pin file, both of which cargo/rustup act
on mechanically.

## Why this verdict and not an adjacent one

- Not **partial**: every crate in the workspace inherits the workspace MSRV;
  there is no member with a different or missing `rust-version`.
- Not **stronger-than-spec**: the appendix row documents an MSRV plus the
  machine's newer compiler (1.94.1); pinning the build toolchain to exactly
  1.89.0 is the natural way to make an MSRV meaningful in a
  verified-build workspace, and the README's "pinned" language matches the
  appendix's intent rather than exceeding it. The declared MSRV value is
  exactly what the spec names.
- Not **contradicted/absent**: the value 1.89.0 appears in Cargo metadata,
  toolchain pin, and docs, all agreeing.

One reading note: the requirement says MSRV **1.89** and the machine has 1.94.1,
yet `rust-toolchain.toml` forces builds onto 1.89.0 exactly. That is consistent
with the appendix (an MSRV of 1.89 is satisfied by building with 1.89.0) and
with the README's explicit pin; it is a deliberate reproducible-build choice,
not a discrepancy against REQ-04.
