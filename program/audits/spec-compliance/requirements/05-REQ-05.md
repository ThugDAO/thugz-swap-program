## Requirement (verbatim)

> **Commit `Cargo.lock`.** Platform-tools versions below v1.52 bundle a cargo that cannot
> build `edition = "2024"`, and several transitive crates now require it. A committed lockfile
> is what stops that appearing months later on a different machine.

Holds-if condition given by the caller: "Cargo.lock is checked into the repo (not gitignored)."

## Verdict

**implemented** — confidence **high**.

## What the requirement demands

This is a repository-hygiene requirement, not a code-path requirement. It demands exactly one
thing: the workspace's `Cargo.lock` is tracked by git (so builds on other machines resolve the
same transitive crate versions), and no ignore rule excludes it.

## Where enforcement lives

- `git ls-files | grep -i cargo.lock` → `program/Cargo.lock` — the lockfile is tracked.
- The workspace root is `program/Cargo.toml` (the only non-target `Cargo.toml` besides the
  program crate's own manifest at `program/programs/thugz-swap/Cargo.toml`), so
  `program/Cargo.lock` is the lockfile for the whole Anchor workspace containing
  `programs/thugz-swap`. There is no other workspace needing its own lockfile.
- The file is a real generated lockfile, 6,066 lines, header (`program/Cargo.lock` L1–L3):

  ```
  # This file is automatically @generated by Cargo.
  # It is not intended for manual editing.
  version = 4
  ```

- `git check-ignore program/Cargo.lock` returns nothing (exit non-zero → NOT ignored).
- Neither ignore file excludes it:
  - `program/.gitignore` contains only `target/`, `.anchor/`, `.surfpool/`, `node_modules/`.
  - Repo-root `.gitignore` (secrets, caches, `recovered/*`, docs) has no `Cargo.lock` or
    `*.lock` pattern.
- Commit history: `git log --oneline -1 -- program/Cargo.lock` →
  `53cf354 program: Phase 3 — devnet matrix 40/40, Level 2 property suite, deploy lesson recorded`
  — the lockfile is committed, most recently in that commit.
