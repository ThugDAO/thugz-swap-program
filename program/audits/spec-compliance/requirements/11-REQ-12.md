# REQ-12 — Treasury PDA is the rent payer, system-owned, zero data

## Requirement (verbatim)

> "Use a separate **`["treasury"]` PDA, system-owned, zero data**, which signs as payer via
> seeds. Closed-account rent returns there. An earlier draft had `Pool` paying and would have
> failed on the first deposit and the first swap."

— IMPLEMENTATION_APPENDIX.md §2, "The rent payer cannot be `Pool`" (L93–L100).
Holds-if: all rent payments are funded by the `["treasury"]` PDA signing via seeds; the
treasury stays system-owned with zero data.

## Verdict

**implemented** — confidence **high**.

## What the requirement demands

1. Every account the *program* creates (Mapping accounts, all ATAs) has its rent funded by
   the PDA derived from `["treasury"]`, and that PDA authorizes the payment via
   `invoke_signed` seeds, never a keypair.
2. The treasury account remains a plain system account with zero data forever — no `init`,
   `allocate`, or `assign` ever touches it (SWAP_SPEC.md L118–L121: "Never `init`,
   `allocate` or `assign` this account… The first `assign` to this program kills it as a
   legal `create_account` payer").
3. Closed-account rent (from `fix_mapping`) flows back to the treasury.

Scope note: the appendix's own framing limits the rule to what the program funds — "`Pool`
carries data, so it can never be the payer for **Mapping init or ATA creation**"
(IMPLEMENTATION_APPENDIX.md L95–L96). The Pool account's *own* rent at `initialize_pool` is
paid by the admin keypair, which no document assigns to the treasury (SWAP_SPEC.md L138
lists `initialize_pool` under signer "admin").

## Where enforcement lives

### 1. The single ATA-creation helper — treasury pays, signs via seeds

`program/programs/thugz-swap/src/instructions/mod.rs` L35–L58:

```rust
pub(crate) fn create_ata_idempotent_treasury_pays<'info>(
    treasury: &SystemAccount<'info>,
    treasury_bump: u8, ...
) -> Result<()> {
    let seeds: &[&[u8]] = &[TREASURY_SEED, &[treasury_bump]];
    associated_token::create_idempotent(CpiContext::new_with_signer(
        AssociatedToken::id(),
        associated_token::Create {
            payer: treasury.to_account_info(), ...
        },
        &[seeds],
    ))
}
```

`TREASURY_SEED = b"treasury"` (`src/constants.rs` L6). The payer is the treasury account,
the CPI is `new_with_signer` with the `["treasury", bump]` seeds — exactly "signs as payer
via seeds". The doc comment (mod.rs L26–L33) records why this must be an explicit CPI:
Anchor `init`/`init_if_needed` cannot sign for a PDA payer (appendix §4, L204–L212 agrees).

Every ATA the program creates goes through this helper — there is no other ATA-creation or
`create_account` call in `src/` (see searches):

- `swap.rs` L103–L110 (vault_original_ata) and L112–L120 (holder_new_ata) — matches
  SWAP_SPEC.md L165–L166 "rent paid by treasury".
- `deposit_bird.rs` L154–L162 (vault ATA).
- `fix_mapping.rs` L81–L89 (custodian ATA).
- `recover.rs` L81–L89 (custodian ATA).

### 2. Mapping init — deficit funded by treasury, signed via treasury seeds

`deposit_bird.rs` L88–L104: the rent deficit for the manually initialized Mapping is
transferred **from the treasury**, signed with `[TREASURY_SEED, &[ctx.accounts.pool.treasury_bump]]`:

```rust
let treasury_seeds: &[&[u8]] = &[TREASURY_SEED, &[ctx.accounts.pool.treasury_bump]];
system_program::transfer(
    CpiContext::new_with_signer(..., Transfer { from: ctx.accounts.treasury..., to: mapping_info... },
        &[treasury_seeds]), required.checked_sub(existing)...)?;
```

The subsequent `allocate`/`assign` (L113–L135) are signed by the *Mapping* PDA's own seeds —
correct, since those operations cost no lamports and must be authorized by the account being
shaped, not the payer. The funding leg is the treasury's alone.

### 3. Treasury stays system-owned, zero data

- **Type-level re-assertion every call**: the treasury is declared
  `SystemAccount<'info>` with `seeds = [TREASURY_SEED], bump = pool.treasury_bump` in all
  four instructions that use it — `deposit_bird.rs` L58–L59, `swap.rs` L69–L70,
  `fix_mapping.rs` L57–L58, `recover.rs` L58–L59. Anchor's `SystemAccount` checks
  `owner == system_program::ID` on deserialization, so an assigned treasury fails loudly
  (the doc comment at deposit_bird.rs L55–L57 states this intent).
- **Never initialized**: `initialize_pool.rs` L38–L43 deliberately only computes and stores
  the bump — "The treasury account itself is deliberately NOT touched here: it must stay
  system-owned with zero data" — and L56 stores `pool.treasury_bump`. No `init` constraint
  targets the treasury anywhere.
- **No allocate/assign path**: the only `system_program::allocate`/`assign` calls in the
  program are the Mapping ones (`deposit_bird.rs` L113, L123), signed with Mapping seeds.
  Since the treasury is a PDA of this program, only this program can produce its signature,
  and no code path signs an allocate/assign with treasury seeds — so zero-data cannot be
  broken by anyone, on-chain or off.
- **Zero-data caveat on `SystemAccount`**: Anchor's `SystemAccount` checks ownership, not
  data length. That is sufficient here because a system-owned account can only acquire data
  via `allocate`, which needs the treasury's PDA signature (see previous bullet). The ATA
  program's inner `create_account` is also a runtime backstop: it rejects a data-bearing
  payer (mod.rs L31–L33).

### 4. Closed-account rent returns to the treasury

`fix_mapping.rs` L23–L28: `#[account(mut, close = treasury, seeds = [MAP_SEED, ...])]` —
the Mapping's lamports go to the treasury on close (doc comment L20–L22: "Rent returns to
the treasury (never Pool, never admin)"). A lamport credit does not alter owner or data.

### 5. Test evidence (not enforcement, but confirms the invariant is exercised)

- `tests/level1.rs` L389–L392: after `initialize_pool`, asserts
  `t.owner == system_program::ID` and `t.data.len() == 0`.
- `tests/level1.rs` L460–L482: fix_mapping rent-return assertion ("rent did not return to
  treasury").
- `tests/level1.rs` L891–L904: drained-treasury deposit fails legibly.
- Treasury funded in tests by plain transfer/airdrop to the derived address
  (level1.rs L92–L95), matching SWAP_SPEC.md L118–L119.

## Searches

- `grep -rn "treasury" src/` — 60+ hits; all payer roles route through the helper or the
  deposit deficit transfer; no other treasury use.
- `grep -rn "payer|init|init_if_needed|create_account|allocate|assign" src/` — the only
  Anchor `init` is Pool (`initialize_pool.rs` L20, `payer = admin`); the only
  allocate/assign are Mapping's (deposit_bird.rs L113, L123); the only CPI `payer:` is
  `payer: treasury` (mod.rs L48). No `create_account` call exists; no `init_if_needed`
  anywhere.
- `grep -rn "SystemAccount" src/` — 6 hits: the four treasury declarations plus imports;
  no other account is typed SystemAccount, and the treasury is never typed anything else.
- `grep -rn "treasury" tests/` — funding by plain airdrop to derived address; invariant and
  rent-return assertions as cited above.

## Why this verdict and not the adjacent one

Not **partial**: every program-funded rent event (both Mapping init and all five ATA
creations across four instructions) routes through the treasury with seed signing — no path
pays from Pool, admin, or any other account. The single non-treasury rent payment, Pool's
own rent in `initialize_pool`, is the account the appendix rule exists to *exclude as a
payer*, and both documents assign that instruction to the admin signer; reading REQ-12 to
demand treasury-paid Pool rent would also be circular (the treasury bump is recorded during
that same instruction). Not merely name-based: the helper was opened and its payer/signer
fields verified; the deposit deficit transfer was read line by line.

## Open questions

- `SystemAccount` does not itself assert `data_is_empty()` on the treasury. The zero-data
  half of the invariant rests on the impossibility of an unauthorized `allocate` (needs the
  PDA signature only this program can produce, and no such call exists) plus the ATA
  program's runtime rejection of a data-bearing payer. This is sound but indirect; a
  belt-and-braces `constraint = treasury.data_is_empty()` would make it local. Not a
  compliance gap against the requirement as written.
