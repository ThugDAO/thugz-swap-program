# REQ-16 — Custodian as compile-time constant in deposit/fix/recover

## Requirement (verbatim)

From /home/david/claude/thugbirdz/IMPLEMENTATION_APPENDIX.md §2, Seeds (as supplied to this review):

> "Deposit source owner; fix_mapping and recover destination. A compile-time constant,
> deliberately — an init-time field could be mis-set to admin, which would put admin
> back in the destination seat."

Holds if: deposit_bird source is owned by CUSTODIAN; fix_mapping and recover send
tokens to CUSTODIAN's ATA; the custodian key is never taken from instruction data or
pool state.

## Verdict

**implemented** — confidence **high**.

## What the requirement demands

1. `CUSTODIAN` must be a compile-time constant, not a Pool field or instruction arg.
2. `deposit_bird` must only accept a source token account owned by that constant.
3. `fix_mapping` and `recover` must deliver the token only to the constant custodian's
   ATA.
4. No path may read the custodian identity from instruction data or from `Pool` state.

## Where enforcement lives

### The constant

`program/programs/thugz-swap/src/constants.rs` L17–L25:

```rust
/// Token custodian (HxwZ): the only legal `deposit_bird` source owner and signer, and
/// the only legal destination for `fix_mapping` and `recover`. ...
#[cfg(not(feature = "test-keys"))]
#[constant]
pub const CUSTODIAN: Pubkey = pubkey!("HxwZCEMgck9v24iP9y2YcBttBkM7GjX77oBiNmQYiiUB");
#[cfg(feature = "test-keys")]
#[constant]
pub const CUSTODIAN: Pubkey = pubkey!("FmsQWrqdWwvjREEB1CmD7w1hrzz2coXq8SxxAj9bLQZZ");
```

A `const Pubkey`, compiled in. The `test-keys` variant is a committed fixture for the
test build only (README/constants.rs doc: mainnet artifact built with default
features); the default build carries HxwZ.

### deposit_bird — source owned by CUSTODIAN

`src/instructions/deposit_bird.rs`:

- L24–L25: `#[account(constraint = custodian.key() == CUSTODIAN @ SwapError::NotCustodian)]
  pub custodian: Signer<'info>` — the custodian account is a **Signer** pinned to the
  constant.
- L31–L36 (accounts struct): `constraint = source_ata.mint == new_mint.key()` and
  `constraint = source_ata.owner == CUSTODIAN @ SwapError::NotCustodian` — the source
  token account's owner field is compared to the constant directly, not to the passed
  account.
- L165–L172: the `transfer_checked` CPI uses
  `authority: ctx.accounts.custodian.to_account_info()` — so the transfer can only
  succeed with the constant custodian's signature as token owner (no delegate path:
  the account is a `Signer` and the SPL owner check binds `source_ata.owner`).

### fix_mapping — destination is ATA(CUSTODIAN, new_mint)

`src/instructions/fix_mapping.rs`:

- L48: `#[account(constraint = custodian.key() == CUSTODIAN @ SwapError::NotCustodian)]`
  on the (unsigned, wallet-only) custodian account.
- L74–L79: handler asserts the destination address against the **constant itself**,

- L92–L99: `transfer_checked` with `to: ctx.accounts.custodian_ata.to_account_info()`.

### recover — same pattern

`src/instructions/recover.rs`:

- L50: `constraint = custodian.key() == CUSTODIAN @ SwapError::NotCustodian`.
- L74–L79: `require_canonical_ata(&ctx.accounts.custodian_ata.key(), &CUSTODIAN, ...)`
  — again against the constant.

### The helper actually checks the bound

`src/instructions/mod.rs` L60–L76, `require_canonical_ata`: computes
`get_associated_token_address_with_program_id(wallet, mint, token_program)` and
`require_keys_eq!(*ata, expected, err)`. It is unconditional — no branch skips the
comparison — and both callers pass `&CUSTODIAN` (the constant) as `wallet`. The
subsequent `create_ata_idempotent_treasury_pays` (mod.rs L34–L57) CPIs into the ATA
program's `create_idempotent`, which re-validates canonical derivation.

### Never from instruction data or pool state

- Instruction signatures (`src/lib.rs` L36–L77): `initialize_pool(unlock_ts, collection)`,
  `deposit_bird(old_mint)`, `fix_mapping(old_mint)`, `recover(old_mint)`,
  `set_paused(paused)`, `seal()`, `swap()`. No instruction takes a custodian pubkey.
- `Pool` struct (`src/state.rs` L10–L23): fields are admin, collection, expected,
  deposited, swapped, recovered, sealed, paused, unlock_ts, bump, vault_bump,
  treasury_bump. **No custodian field.**
- `grep -rn custodian` over `initialize_pool.rs` and `swap.rs`: zero hits — the
  identity is never initialized or stored anywhere.

## Paths walked

- deposit_bird happy path: constraints at struct level (Anchor evaluates before the
  handler) → handler transfer with custodian as signing authority. Enforced.
- fix_mapping: struct constraint on `custodian`, then handler `require_canonical_ata`
  against `&CUSTODIAN` before the ATA-create CPI and the outbound transfer. Even if
  the `custodian` account constraint were absent, the destination address check binds
  to the constant. Enforced on the only path (no early returns before the check).
- recover: identical structure; the `require_canonical_ata` sits before the transfer,
  unconditionally. Enforced.
- Cross-check: `swap.rs` (holder path) and `seal.rs` do not move tokens to any
  custodian-named account, so no bypass path exists there for this requirement.

## Why this verdict and not the adjacent one

Not **partial**: every token-moving path named by the requirement (deposit source,
fix_mapping destination, recover destination) checks against the compiled constant,
and the handler-level ATA derivation checks use `&CUSTODIAN` directly rather than the
caller-supplied `custodian` account key — so even the account-substitution angle is
closed. Not **stronger-than-spec** in any material way: the extra requirement that the
custodian *signs* deposit_bird (deposit_bird.rs L25) is itself demanded elsewhere in
the spec corpus (constants.rs doc: "source owner and signer"), so it is in-spec.
